# SkyblockAddon (Skyvault line): phase R plan for Update 4

Source of truth for the findings and sir's answers: `/mnt/data/Projects/skyvault-update4-2026-11-20/9-mod-review/findings/15-skyblockaddon.md` (B1-B14, F1-F7, cleanup stages, upstream comparison, answers 2026-11-21). The previous ItemGrid redesign plan was superseded by the ListView redesign (`efe1458`) and is in git history.

Branch `main` (created 2026-11-21 from `gui-redesign` at `5e191cd`; sir: this becomes the main line and ships as 10.0, one version for Remastered and Wolds). `main` is pushed to `origin` and is the GitHub default branch since 2026-11-22 (sir's go after the testnet QA). `remastered`, `gui-redesign` and the wolds branches stay as they are (archived after the Wolds switch, never deleted). Wolds sibling (`SkyblockAddon-Wolds`) is read only: fixes are ported from it, never edited there.

## Decisions (sir, 2026-11-21)

- Keep our line; port the Wolds fixes (`118925f`, `1097a69`, `3b174ba`, `4a32988`, `76933b7` where still relevant) and these upstream (`YorickBM/SkyblockAddon` `Version-8.X`) additions, adapted to our permission checker: Easy Villagers / Easy Piglins mixins, Vault Portal / Nether Portal / Elevatorid mixins, console-usable admin commands. No upstream permission-engine change, no altar debounce.
- Every bug B1-B14 is fixed as recommended; all six cleanup stages run before the deploy; F1-F5 and F7 are built before the deploy, F6 as a read-only report.
- Independent review of the fix diff: Fable subagent (dupe/item-loss risk), given code and spec only.

- One line for both servers (sir, 2026-11-21): after the U4 deploy, `gui-redesign` becomes the single branch for Skyvault (Remastered) and Wolds. Until then the Wolds line gets one R1-only hotfix (9.12) once the R1 fix here is tested; deploying it to the live Wolds servers still needs sir's per-action go.

## Decisions after the testnet QA (sir, 2026-11-22)

- W0: ship Wolds 9.12 as built (`hotfix-9.12-r1` `46afbaf`, R1 + S9 Quark mixin). Fable findings 3-7 on the Wolds line wait for 10.0 (W3). Before any deploy: Wolds testnet boot + visitor reacharound check (mixin applies, block and trowel denied); live deploy only with sir's per-action go.
- Push `main` to `origin` and make it the GitHub default branch (push-check first).
- W0 live deploy (sir, 2026-11-22, after P8): do NOT deploy 9.12 to the live Wolds servers; wait for the unified 10.0 (W3). The R1 visitor hole stays open on live Wolds 9.11 until then. 9.12 (`hotfix-9.12-r1` `46afbaf`) stays built and tested, unused unless sir asks.
- Demotion to Visitors = removal: assigning the Visitors group to a member removes them from the island like a kick (they can then create or join another island).
- Set spawn requires the player on ground with a solid block under them, inside the island bounds.
- Group names: strip the `[...]` brackets on create and on island load; commands match a group name with or without brackets.
- Purge of an abandoned island with an empty chunk list: wording fix only (says abandoned but no tracked chunks, stays refused; protects the carried spawn island).
- `island.nbt`: an unreadable or corrupt config file stops the server at boot naming the file and cause (like B5); no silent fallback to the bundled island.
- `/island ban` lookups: one pending Mojang lookup per player (any name); a second one while pending is refused.
- GUI changes (Fable F8 confirm before Visitors removes a member, any other SkyblockAddon screen work) wait until MasuGUI is done (review 16: 1.1.3 with the button confirm, theme art); then one GUI pass on SkyblockAddon adopting MasuGUI 1.1.3.

## Decisions for W2 (sir, 2026-11-22)

- Buildscape pillar protection on Wolds (Buildscape 3.0.9; the B15 mixin targets 4.x classes): add a second pillar mixin config for the Buildscape 3.x classes, chosen by the installed Buildscape version, so pillars are protected on both packs with no missing-target warnings.
- Fable W1 low F3 (randomizer bag holding a boat or spawn egg places the entity on a foreign island): fix now, the entity placer check judges the bag's inner item.
